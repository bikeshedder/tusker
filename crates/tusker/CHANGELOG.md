# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

It covers the whole tusker project. Every release of a `tusker-*` crate comes
with a release of `tusker`, and each release lists the crates released together
with it. Their changelogs contain the details of the Rust APIs.

## [0.8.0] - 2026-10-02

### Added

- Checked queries support PostgreSQL enums. `tusker query sync` records enum
  types including their labels, and tusker-query checks them against Rust enums
  deriving `QueryEnum`. Enum arrays and nullable enum columns work, too.
- Checked queries support PostgreSQL `numeric` using `rust_decimal::Decimal`
  with the `with-rust_decimal-1` feature of tusker-query.
- Query sidecars record the version of their file format. tusker-query asks you
  to run `tusker query sync` when a sidecar is outdated, and to upgrade
  tusker-query when a sidecar is newer than it supports.

### Changed

- **Breaking:** sidecars generated by `tusker query sync` require tusker-query
  0.4, and tusker-query 0.4 rejects sidecars without a format version. Run
  `tusker query sync` after upgrading.
- Compile errors of checked queries name the parameter or column, its
  PostgreSQL type and the Rust types it maps to, including the feature flag
  required for them. Enum mismatches name the missing or extra labels.

### Fixed

- `tusker migration log` now prints timestamps as `YYYY-MM-DD HH:MM:SS +HH:MM`
  fixing the occasional misalignments.

## [0.7.0] - 2026-07-06

### Added

- Add support for array and composite parameter and result column types in `tusker query` metadata.
- Add the `[diff] removed_enum_value` configuration option (`"unsafe"` — the
  default and previous behavior, `"warn"`, or `"ignore"`) controlling how the
  removal of an enum value is handled by `tusker diff` and `tusker check`.

### Changed

- **Breaking:** the `tusker migration` and `tusker migrate` commands no longer
  accept `--migrations-dir`. Migrations are loaded from the `migrations.filename`
  glob in the configuration file (default `db/migrations/**/*.sql`).
- `tusker check` is now defined as an empty `tusker diff` and defaults to the
  same direction (migrations → schema), so the two commands can never disagree.

### Fixed

- `tusker diff` now reconciles drifted `NOT NULL` constraint names on
  PostgreSQL 18+. A column renamed with `ALTER TABLE ... RENAME COLUMN` kept the
  constraint name derived from its former name, so `tusker diff` reported no
  changes while `pg_dump` still showed a difference; it now emits a
  `RENAME CONSTRAINT` statement to reconcile the two.

## [0.6.0] - 2026-05-22

This is the first release of the Rust implementation of Tusker. It starts at
`0.6.0` to avoid overlapping with version numbers used by the archived Python
implementation on [PyPI](https://pypi.org/project/tusker/).
